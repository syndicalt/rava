Problem

Agent auth gets weird fast.

Human login was built for people sitting in front of screens. Agents act across tools, services, and delegated tasks. A bearer token can answer "who has this token" but it does not naturally explain whether a specific booking, transfer, file write, or API call was actually delegated.

Rava treats authorization as an inspectable object: a signed action, a signed capability chain, and verifier state for replay and revocation. Less hand-waving, more evidence.

Proposed Solution

Make the action carry its authority.

Signed actions

Agents sign exact intent, resource, context hash, nonce, and timestamp data.

Delegated capabilities

Controllers delegate bounded authority. Child capabilities cannot broaden parents.

Verifier receipts

Decisions can be signed, checked later, and correlated with post-action attestations.

Explicit assumptions

Key discovery, custody, distributed freshness, and production operations stay visible.

Full Lifecycle

From delegation to audit trail.

01

Delegate

A controller signs a root capability and narrows it for an agent or subagent.

02

Act

The agent signs a concrete action against a resource, operation, context hash, and nonce.

03

Verify

The verifier checks signatures, expiry, actor binding, attenuation, replay, and revocation.

04

Receipt

The verifier signs an accepted or rejected decision bound to the capability chain hash.

05

Attest

A downstream evaluator signs post-action evidence about what actually happened.

Usage Examples

Concrete commands, not a fog machine.

Run the demo
cargo run -p rava -- demo flight-booking
Verify an action
rava verify action --action action.json --capability-chain capability-chain.json --actor-key <actor-public-key-hex> --issuer-key <issuer-id=issuer-public-key-hex>
Verify a receipt
rava verify receipt --receipt receipt.json --verifier-key <verifier-public-key-hex>
Sign an attestation
rava attest sign --key evaluator-key.json --out attestation.json --action-id act_demo --outcome accepted --subject travel.booking --evidence-hash sha256:<64-lowercase-hex>

Roadmap

Draft complete. Production systems still have to earn it.

  1. V0 draft: complete reference implementation, examples, docs, and release gate.
  2. Review: external security review, remediation tracking, and optional longer fuzz campaigns.
  3. Preview: stable developer-facing package and service surface, with Rust verifier semantics authoritative.
  4. Production: custody, discovery, distributed freshness, caller identity, rate limits, monitoring, and audit storage.
